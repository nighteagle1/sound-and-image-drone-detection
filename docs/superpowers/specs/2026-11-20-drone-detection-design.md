# Обнаружение дронов по звуку и изображению — проектный документ

Дата: 2026-11-20

## Цель и зачем

Учебная демонстрация: показать, как нейросети обнаруживают дрона по звуку
и по видео. Показ идёт либо на записи (аудио или видеофайл), либо с
игрушечным дроном перед микрофоном или камерой. Это не боевая или полевая
система, надёжность в реальных условиях (ветер, большие расстояния)
не требуется.

Пользователь клонирует репозиторий на Raspberry Pi, запускает один `.sh`,
открывается браузер, и в нём можно выбрать режим и обнаруживать дронов.
Тот же проект запускается на Windows.

## Цели

- Два независимых режима: **Звук** и **Изображение**. Одновременно работает один.
- Источники: **микрофон** (звук), **камера** (изображение) и **загруженный файл** (запись).
- Простой и понятный интерфейс в браузере.
- Запуск одной командой на Raspberry Pi (`.sh`) и на Windows (`.bat`).
- Модели только в формате ONNX, инференс через ONNX Runtime (без PyTorch на устройстве).
- Язык: Python.

## Не цели и антицели

- Нет полевой точности, нет подсчёта дальности и определения направления.
- Нет обучения или дообучения моделей в проекте.
- Нет учётных записей, базы данных, облака и записи истории на диск.
- Антицель: сложная установка. Если для запуска нужно больше одной команды
  и ручной правки, это провал, даже если всё работает.

## Подход (решения о том, как строить)

Рассмотрены три варианта:

1. **Сервер сам берёт микрофон и камеру, браузер только показывает** (FastAPI,
   OpenCV, sounddevice, ONNX Runtime; видео как MJPEG, результаты звука через SSE).
   Плюсы: одинаково на Pi и Windows, Pi может работать без монитора,
   страницу можно открыть с другого устройства. Минус: выбор устройства
   через настройки.
2. **Устройства берёт браузер (getUserMedia), на сервер идут кадры и звук.**
   Плюсы: браузер сам предлагает выбор устройства. Минусы: работает только на
   `localhost` или по HTTPS, лишний трафик.
3. **Streamlit или Gradio.** Быстро, но мало контроля над живым видео и звуком.

**Выбран вариант 1** (подтверждено пользователем).

## Модели

| Режим | Модель | Формат | Лицензия |
|---|---|---|---|
| Изображение | [engdarwish/drone-detection-yolov5](https://huggingface.co/engdarwish/drone-detection-yolov5), файл `best.onnx` | уже ONNX | MIT |
| Звук | [AntoineNaccache/drone-audio-detector](https://huggingface.co/AntoineNaccache/drone-audio-detector), вариант `drone_classifier_aug_mixed.pt` | PyTorch, нужна конвертация | MIT |

- Конвертация аудиомодели в ONNX: один раз, ноутбуком на Kaggle через Kaggle CLI
  (у пользователя установлен, авторизован). После конвертации сверить выходы
  ONNX и PyTorch на одном аудио. Готовый `.onnx` кладётся в репозиторий или
  скачивается скриптом установки (решает строитель, см. ниже).
- Модели лежат в `models/`, пути задаются в конфиге. Замена модели не требует
  правки кода.
- Звуковая модель: вход — лог-мел-спектрограмма (64 полосы, 16 кГц, моно, окно 1 с,
  перекрытие 50%). Параметры спектрограммы (`n_fft=512`, `hop_length=160`,
  `f_min=50`, `f_max=5500`) берутся из `config.yaml` модели. Выход — логит,
  вероятность = sigmoid.
- Запасной вариант для изображения, если выбранная модель не подойдёт:
  [sapoepsilon/yolov11s-drone-detector](https://huggingface.co/sapoepsilon/yolov11s-drone-detector)
  (Apache-2.0, `.pt`, потребует конвертации).

## Поведение и интерфейс

Одна страница. Вкладки **Звук / Изображение**. Работает один режим,
модель другого не загружается.

- **Источник:** в режиме «Звук» — микрофон или файл (`.wav`/`.mp3`); в режиме
  «Изображение» — камера или видеофайл. Для устройств есть выпадающий список.
- **Звук:** крупный индикатор «Дрон обнаружен / не обнаружен», текущая
  вероятность, график вероятности за последние 30 с.
- **Изображение:** видео с рамками и уверенностью, счётчик FPS.
- **Порог срабатывания** — ползунок (по умолчанию 0.5 для звука; для изображения
  своё значение по умолчанию). Нужен, потому что игрушечный дрон тише, а в
  помещении есть посторонний шум.
- Кнопки «Старт» и «Стоп». Понятные сообщения об ошибках на странице
  (нет микрофона или камеры, файл не читается, модель не найдена).
- Файл-источник воспроизводится через модель по времени записи (звук) или
  покадрово (видео), чтобы показ выглядел как живой.

Эскиз:

```
[ Звук ]  [ Изображение ]            Источник: ( ) Микрофон  ( ) Файл
┌──────────────────────────────────────────────────────┐
│  ДРОН ОБНАРУЖЕН            вероятность 0.93          │
│  ▁▂▂▃▇▇▇█▇▆▃▂▁  график за 30 с                       │
└──────────────────────────────────────────────────────┘
Порог: ──────●────  0.50        [ Старт ] [ Стоп ]
```

## Ограничения и известные риски

- Звуковая модель обучена на датасете, где «не дрон» — в основном бытовые и
  речевые звуки. На показе возможны ложные срабатывания (разговор, музыка,
  пылесос) и пропуски для тихого игрушечного дрона. Поэтому порог настраивается.
- Заявленные метрики моделей (F1 0.9996 для звука, mAP50 99% для изображения)
  получены авторами на их данных, на показе не гарантируются.
- Целевое железо — Raspberry Pi, FPS изображения ожидается порядка 15–20 на Pi 4 (по
  заявлению автора модели), на Pi проверяется отдельно.

## Решения, принятые при проверке документа (мои решения, не пользователя)

- **Конвертация звука — первая задача и точка риска.** Архитектуру модели брать из
  `model.py` репозитория модели, веса загружать как `model_state_dict` (если ключ есть),
  экспортировать в ONNX (FP32, динамическая ось времени), сверить с PyTorch на
  реальном аудио (допуск порядка 1e-4 на вероятности). В README модели загрузка идёт с
  `strict=False`: проверить, что ключи действительно совпали, иначе веса не загрузились.
  Если конвертация не удалась и починить нельзя, выпускаем сначала режим «Изображение», а режим
  «Звук» выключаем в интерфейсе с понятным сообщением, и возвращаемся к нему отдельно.
- **Предобработка звука — эталон из README модели:** моно, 16 кГц, Hann-окно 512,
  hop 160, 64 mel, 50–5500 Гц, `MelSpectrogram` (степень 2) → `AmplitudeToDB` (по умолчанию в
  torchaudio: 10·log10, top_db=None) → `(x + 40) / 40`. Реализовать на NumPy (без
  PyTorch и torchaudio на устройстве) и протестировать совпадение с torchaudio на
  тестовых сигналах; torchaudio нужен только в тесте и на Kaggle. mel-шкала и
  нормировка фильтров — как в torchaudio по умолчанию (HTK, без нормировки).
- **Сглаживание звука.** «Дрон обнаружен» определяется по вероятности окна, но чтобы
  индикатор не мигал, показывается состояние с задержкой: включение при превышении порога
  в двух окнах подряд, выключение после двух окон ниже порога. Сырая вероятность
  рисуется на графике.
- **Изображение:** один порог уверенности (ползунок) и фиксированный NMS IoU 0.45;
  вход и letterbox — как в `data yaml`/README репозитория модели.
- **Файлы.** Звуковой файл проигрывается сервером в реальном времени (по 500 мс шагам) и
  не воспроизводится в браузере. Видеофайл идёт с исходным FPS. В конце файла источник
  останавливается. Смена источника — через «Стоп» → выбор → «Старт», без перезапуска сервера.
  Формат `.mp3` не обязателен: гарантируются `.wav` и видео-форматы, которые читает OpenCV; `.mp3` — только если
  декодер доступен без лишних системных зависимостей.
- **Сеть.** По умолчанию сервер слушает только `127.0.0.1`. Доступ с других устройств включается
  явным параметром запуска (`--host 0.0.0.0`) с предупреждением, что страница без авторизации
  открывает камеру и микрофон. Один зритель; многопользовательский режим не нужен.
- **Платформы.** Raspberry Pi 4/5, 64-bit Raspberry Pi OS (Bookworm), Python 3.11+. Windows 10/11,
  Python 3.11+. `run.sh` проверяет наличие системных пакетов (`libportaudio2` и т. п.) и, если их нет,
  выводит точную команду `sudo apt install ...` и сам ничего с `sudo` не запускает.
- **Где модели.** Оба `.onnx` лежат в самом репозитории (`models/`): суммарно десятки
  мегабайт, лицензии MIT, интернет при первом запуске не нужен (нужен только для установки
  пакетов). Файл звуковой модели создаётся конвертацией на Kaggle и коммитится один раз.
- **Переключение вкладки** останавливает текущий режим и выгружает его модель.

## Что остаётся строителю

- Структура каталогов, конфиг-формат, имена файлов.
- Выбор между FastAPI и Flask, способ передачи результатов в браузер (SSE или WebSocket).
- Скрипты установки и запуска (`run.sh` для Pi и Linux, `run.bat` для Windows):
  создание виртуального окружения, установка зависимостей, открытие браузера.
- Хранить `.onnx` в репозитории или скачивать при установке (с учётом размера и лицензии).
- Предобработка кадра для YOLOv5 ONNX (размер входа, letterbox, NMS) по данным из
  репозитория модели; значение порога по умолчанию для изображения.
- Тесты (предобработка, постобработка, граничные случаи источников).
- Версии библиотек, совместимые с Python на Pi OS и Windows.
